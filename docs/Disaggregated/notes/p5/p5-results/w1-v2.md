## 1. Finding 1 — an empty `SEG_STAGE` now takes a blob that fits (`1a06b40a`)

**What was wrong.** `m_stageHead` / `m_stageTail` are monotonic byte counts, so "every staged
byte has retired" reads `head == tail`, **not** `head == tail == 0`, and `head % capacity` is
left wherever the last run ended. `StageAllocate` then charged a wrap skip against that offset:
with `head == tail == 64` in a 256 KiB stage the test became `2*capacity − 64 <= capacity`,
false at **every** occupancy, and `ReclaimStagedBytes()` cannot move an already-empty tail — so
the second attempt failed identically and the request aborted on
`Fatal{RingOverrun, "SEG_STAGE"}`, whose own message then printed `0 bytes still in flight`.

**What changed.** A new private `PipeWireEncoder::RebaseEmptyStage()`, called at the top of each
of `StageAllocate`'s two attempts — so it also runs *after* `ReclaimStagedBytes()`, which is the
review's scenario (8 MiB allocated, retired, then a 28 MiB request). When `head == tail != 0` it
resets both cursors to zero. **The general statement, as the verifier asked: the wrap skip may
only be charged against bytes that are actually still in flight, and when there are none the
allocator restarts at offset 0.**

**One thing the fix shape did not mention and the code needs.** The mark queue has to be rebased
with the cursors. A `StageMark` holds the **absolute** head cursor it was pushed at, and
`ReclaimStagedBytes` assigns that value straight to `m_stageTail`. Every mark not yet consumed
has `StageCursor <= head == tail` (the head is monotonic and marks are pushed in order), so each
one names a region that is already reclaimed and zero is the truthful rebasing of it. Without
that, one reclaim after a rebase would put the tail **ahead of** the head and
`StagedBytesInFlight()` would underflow to ≈2⁶⁴. `RebaseEmptyStage` rewrites them.

**Control.** The verifier's extension of
`PipeWireCodecTest.StagedBytesAreReclaimedOnlyBehindRetiredSeq`, kept: after the 64-byte
allocation retires and in-flight is zero, `StageBytes` of exactly `Wire2::kStageBytes` must land
at `Offset == 0`, in `kSegStage`, resolve back to `StageBase()`, and leave
`StagedBytesInFlight() == kStageBytes`.

> `StageAllocate`'s attempt loop.** Executed (`~/w7/p5-w1-redcheck2.log`):
> `1946 - PipeWireCodecTest.StagedBytesAreReclaimedOnlyBehindRetiredSeq (Subprocess aborted)`,
> `0% tests passed, 1 tests failed out of 1` — the verifier's exact outcome. Green again on

### The exact maximum blob an empty stage takes — and the correction to `w1-v1.md:341`

`need = Align8(size)` and the first bound is `need > m_stageCapacity`, so **an empty stage takes
a blob of exactly `m_stageCapacity` bytes** (more precisely `floor(capacity / 8) * 8`; every
canonical capacity is 8-aligned, so the two are the same number).

`m_stageCapacity` is the stage `RingProducer`'s `Capacity()` when one is installed and the whole
`SEG_STAGE` view size otherwise. **In a real session there is no stage ring at all** —
`SessionRings.h:83-88`: `SEG_STAGE` is "an encoder-local LINEAR ALLOCATOR … a plain byte count:
no control page, and no rounding down to a power of two either" — so `m_stageCapacity ==
SessionSegmentSizes::StageBytes == MOBILEGL_IPC_STAGE_MB`, i.e. **33,554,432 bytes at the
default 32**. In the unit fixture it is `Wire2::kStageBytes` = 262,144, which is what the new
assertion pins.

**`w1-v1.md:341` said "The archive's bound is `MOBILEGL_IPC_STAGE_MB` (32 MiB)". The verifier
falsified it, and it was false: before this fix, the bound on an empty stage was**

```
max( head mod capacity , capacity − (head mod capacity) )
```

— i.e. anywhere from **half** the segment to all of it, equal to the full 32 MiB only on a
*fresh* encoder whose head is still 0. (The verifier's discriminator, `FINDING1B: fresh encoder
ALLOCATED offset=0 size=262144`, is exactly that boundary case.) **After this fix the sentence
is true as written**: the bound is `MOBILEGL_IPC_STAGE_MB`, 32 MiB by default, at every
occupancy at which the stage is empty.

### Does R-10's max-record counter see it? **No — and that is now pinned.**

`m_maxRecordBytes` is fed from `layout.TotalBytes` in `EncodeRecord` — header + payload + tails,
all of it `SEG_CMD` — while a staged blob leaves only `{Seg, Offset, Size}` (24 bytes) in the
record. The same control asserts `MaxRecordBytesSeen()` is **unchanged** across a
quarter-megabyte `StageBytes`. So `MaxRecordBytesSeen()` is **not** the staging bound and must
not be read as one: `SEG_STAGE` has its own bound and its own named
`Fatal{RingOverrun, "SEG_STAGE"}` (the message cites `MOBILEGL_IPC_STAGE_MB`), and `SEG_CMD`'s
`RingProducer::MaxRecordBytes()` is what R-10's counter is measured against. Both numbers are
printed live by their own Fatal; neither is a compile-time constant in this file.

## 2. Finding 3 — a content blob must declare `SEG_STAGE` (`ba6dc4f7`)

**What was wrong.** The only test was that the run resolved *inside some* segment, so
`CreateSamplerState.Parameters={Seg=SEG_REPLY, Offset=0, Size=sizeof(SamplerParameters)}` was
accepted by the encoder **and** the decoder, and the sampler applier received those bytes out of
a **server-owned** pool whose reuse has nothing to do with stage retirement. The audit's half
was worse: `NoteResolvedRun` opened with `if (blob.Size == 0 || blob.Seg != kSegStage) return;`,
so the run was never recorded, `PoisonedStageBytes()` stayed zero, and rule C's only mechanical
control was dark on exactly the record it exists to catch — the verifier's probe printed
`seg=3 accepted=1 poisoned=0` with the audit **on**.

**What changed, and where — this is stronger than the fix shape.** The verifier named
`RequireDeclaredBlob`. The arm went one level down, into **`CheckBlobIsHonest`**, because
`RequireDeclaredBlob` is only the "this record says it carries content" path: the **optional**
arms (`CreateRenderState`/`SetDynamicState` with `ChunkMask == 0`, `ResourceSubData` with no
content, `BufferSubDataResident`, `CreateShaderState.Spirv[i]`) and the **encoder's** per-slot
honesty loop call `CheckBlobIsHonest` directly, and a fix in `RequireDeclaredBlob` alone would
have left every one of them accepting `SEG_REPLY`. `RequireDeclaredBlob` calls
`CheckBlobIsHonest`, so it is covered too.

The arm runs **before** the resolve, deliberately: a forged `SEG_REPLY` run that happens to lie
inside a mapped reply pool must be refused for naming the wrong carrier, not left to pass or
fail on whether that pool is mapped at all.

**Which Fatal family, and why.** `Fatal{ProtocolCorruption, "<op>.blob"}`, **not** a new
`BlobNotStaged`. The families are the vocabulary the operator and the CI greps share —
`ProtocolCorruption`, `AbiMismatch`, `UnmigratedVerb`, `UnmigratedPipeInput`, `UnsetCallMask`,
`RingOverrun`, and no other appears anywhere in `MG_Remote` — and a one-off seventh name would
be a token nothing else in the tree recognises. The **segment** is in the message, which is the
part that has to be greppable: `seg=%u offset=%llu size=%llu is not SEG_STAGE(%u)`, plus the
citation of contract table 1 groups A/B/C and R-10.

**The audit's bookkeeping is now unreachable rather than load-bearing.** `NoteResolvedRun`'s
`blob.Seg != kSegStage` case was a silent `return`; it is now a named Fatal of its own, matching
the run-count overflow Fatal immediately below it, and its single caller (`ResolveOrFatal`) runs
`RequireDeclaredBlob` first — so it cannot be reached and says so if it ever is. The verifier's
"either cover the carrier or be unreachable for anything but `SEG_STAGE`" is satisfied by the
second branch.

**Controls.** Two new forked cases, both in the file's own Fatal-arm idiom (`RunInChild` +
`DiedOfAbort` + a **required diagnostic substring**, never `EXPECT_DEATH`):

- `AContentBlobCarriedOutsideSegStageIsFatalAtTheDecoder` — the verifier's perturbed sampler
  fixture kept as its own case, **with `SetAuditPoison(true)` armed**, so the second half of the
  finding is nailed too: with the poison on, the record must *die* rather than be applied with
  `PoisonedStageBytes()` at zero. Requires `is not SEG_STAGE`, `CreateSamplerState.blob` and
  `seg=3` in the child's log.
- `TheEncoderRefusesTheNonStageCarrierTheDecoderCallsFatal` — the symmetry this file already
  states one arm over: under `inproc` a `SEG_REPLY` pointer resolves, so an emitter that staged
  into the reply pool would get a valid seq locally and a Fatal on a peer.

> **I made them red once, by doing X: X = removing the `kSegStage` requirement.** Executed
> twice, both recorded in `~/w7/p5-w1-redcheck2.log`:
> **(a)** deleting only the `blob.Seg != kSegStage` arm — both cases red
> (`0% tests passed, 2 tests failed out of 2`);
> **(b)** the full wave-1 revert, that arm **and** `NoteResolvedRun`'s silent `return` — both

## 3. Finding 4 — the codec's `MapPersistent` arm goes through the tier gate (`bb6ba282`)

**What was wrong.** `AdoptTier` had **zero** references anywhere on the codec path; the arm was
an unconditional `PostReply(..., kStatusDeclined, nullptr, 0); return true;`. `ConfigLoader.cpp`
accepts 0, 1 and 2, so `MOBILEGL_IPC_ADOPT_TIER=0` and `=1` — which contract §5 promises "parse
and are `Fatal` at use, naming P11" — decoded as an ordinary DECLINED on both forbidden tiers,
and an operator got a run that looked like a working T0.

**What changed.** The arm now asks `MG_Remote::Client::AdoptTierIsEmulate()` (b1's file,
unchanged) behind **the same conjunction the monolith applier uses**,
`MG_Config::Transport != MG_Config::TransportMode::Monolith` — `PipeApply.cpp`'s guard,
verbatim, so the two paths cannot drift. The return value is deliberately not a branch: the
helper returns `true` at T2 and **aborts** at T0/T1 on its own named diagnostic, and R-6 says P5
declines at every tier it survives.

**Controls** — three, and the third is what keeps the first two honest:

- `AdoptTierZeroIsFatalOnTheWirePathAndNamesP11` and
  `AdoptTierOneIsFatalOnTheWirePathAndNamesP11`. Forked, not `EXPECT_DEATH` (the file's header
  forbids it: `EXPECT_DEATH` re-runs the whole binary and re-enters the applier's globals).
  **The diagnostic is required, not optional** — `ID-46` finding 10 is an empty death regex, and
  these are its opposite: each case requires the literal
  `MOBILEGL_IPC_ADOPT_TIER=0 names adoption tier T0, which P11 implements`
  (and `=1 … T1 …`) in the child's log, and prints that log when it fails, so a crash for any
  other reason fails the case.
- `TierTwoUnderSplitTransportStillDeclinesRatherThanRefusing` — the positive half. Without it
  the two death cases could be satisfied by an arm that aborted on *every* tier, which is the
  opposite mistake. T2 under `InProcess` transport still answers `kStatusDeclined` with an empty
  payload (R-6), RAII-restored.

> **I made both death cases red once, by doing X: X = restoring the unconditional decline
> (deleting the `AdoptTierIsEmulate` call).** Executed: `33% tests passed, 2 tests failed out of
> 3` — both `AdoptTier*IsFatalOnTheWirePathAndNamesP11` red, and
> `TierTwoUnderSplitTransportStillDeclinesRatherThanRefusing` **still green**, which is exactly
> the discrimination the positive control exists for. Green again on restore.

## 5. What needs an integrator ruling, or at least a decision recorded

**5.1 `GetCaps`'s two blobrefs are now held to `SEG_STAGE` as well, and they are the one
server→client row that owns an `MGPBlobRef`.** Contract §2 row 18 puts `MGPCaps`'s
`FormatCapabilities` and `RendererInfo` in the **server → client** direction, but they are
enumerated by `BlobSlotsFor(GetCaps)` and therefore walked by the encoder's honesty loop and by
the decoder's `GetCaps` arm, both of which call `CheckBlobIsHonest`. **This is inert in P5**: the
caps snapshot travels as a flatbuffer `CtrlEnvelope` out of `ServerSession::PublishCapsSnapshot`
(`ServerSession.cpp:380`), never as record blobrefs, so nothing declares those two and the whole
split unit lane is unaffected — verified, not assumed. But the phase that does carry caps in a
**record** will hit this arm, and at that point either `GetCaps` is exempted by name or the
catalogue grows the per-op *legal segment* column the verifier flagged as the ruling-worthy
version of this fix. **Filed, not taken** — the minimal fix needed no ruling and I did not want
a generated column landing in a rework round.

**5.2 The tier gate carries the applier's `Transport != Monolith` conjunct, including its hole.**
I mirrored `PipeApply.cpp` verbatim so the two cannot drift, which means that a decoder driven
directly under **monolith** transport still skips the tier check. In production that is
unreachable — a record only arrives at the decoder over a wire — and it is exactly ID-42's
finding that a split build under monolith transport mints like push. Only a unit test can be in
that state, and mine sets `InProcess`. If the integrator would rather the forbidden tiers die at
**parse**, that is `ConfigLoader.cpp` = **c0's** file, and `PersistentMapTracker.cpp:118`'s own
comment has already filed it; nothing in this round depends on the answer.

**5.3 No new Fatal family.** I used `ProtocolCorruption` rather than the review's suggested
`BlobNotStaged` (reasoning in §2). If the integrator wants a seventh family it is a one-line
change here plus whatever in CI greps the family names — say so and I will take it.

**5.4 No overlap with s1, ID-47 or the reply geometry.** Worth stating explicitly because
finding 3's fix mentions `SEG_REPLY`: my refusal names `kSegReply` only as an **illegal
client→server blob carrier**, and it lives in `CheckBlobIsHonest`. s1's reply-slot work writes
`SEG_REPLY` through `ReplySlot` / `ReplySink::PostReply`, which carries no `MGPBlobRef` and never
reaches any of these arms; ID-47 moves `SessionSegmentSizes::ReplyBytes` and `ReplySlotCount`,
which none of my files reads. **No shared line, no shared symbol.** The one file s1 and w1 both
have an interest in — `PipeWireCodecTest.cpp` — I touched only in my own cases.
