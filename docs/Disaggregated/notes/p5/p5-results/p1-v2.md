# p1-v2 — wave 1.5, ID-48 finding 9: `gen_pipe.py`'s `expect_trip` accepted any `SystemExit`

## 0. The one-paragraph answer

Same defect as M-1 in `gen_pipe_field_ownership.py` (p1-v1.md §7.1), found again in the sibling
generator by the codex cross-family review (finding 9) and confirmed by execution
(`wave1-codex-verify.md` §9, including the exit-code-zero half). `scripts/gen_pipe.py`'s
`expect_trip` (`:1379`) caught bare `except SystemExit as trip` and asked nothing about which one
or what code it carried, so replacing the flag-typo control's callback (`:1424`) with
`sys.exit("unrelated parser failure")` — or with a **successful** `sys.exit(0)` — still counted as
"tripped as expected", and the harness's own line ("9 negative-control trip(s), positive control
OK") stayed true. Fixed by mirroring the field-ownership generator's shape exactly, plus an R-16
meta-control. Only `scripts/gen_pipe.py` was touched. No C++ changed.

## 1. What changed

`expect_trip(name, fn)` -> `expect_trip(name, because, fn, quiet=False)`:

- Catches `SystemExit`, reads `trip.code`.
- A trip counts **only if `code != 0` AND `because in str(code)`** — the guard's own message,
  not merely that something exited. `because` is required, not inferred.
- `quiet=True` lets a caller probe an exit without it printing as a real control result (used by
  the R-16 meta-control below, so that meta-control cannot itself inflate the trip count).

Each of the nine controls in `self_test()` now carries its own `because` substring, read off the
actual guard it exercises (verified by running the unfixed generator and reading the real
messages, not guessed):

| # | control | `because` |
|---|---|---|
| 1 | struct member without F(...) | `member(s) with no F(...) in PipeFields.def` |
| 2 | F(...) that is not a member | `F(...) name(s) that are not members` |
| 3 | payload with no struct | `struct not found` |
| 4 | verb missing from FillPoints.def | `GLFunctionsTable member(s) without a verb row` |
| 5 | verb not a GLFunctionsTable member | `verb(s) that are not GLFunctionsTable members` |
| 6 | field row naming a non-accessor | `is not an accessor in Coverage.def` |
| 7 | emitted row naming a call that does not exist | `which is not a call in PipeCalls.def` |
| 8 | call flag not an MGPipeCallFlags enumerator | `which is not an MGPipeCallFlags enumerator` |
| 9 | kNone combined with a real flag | `combines kNone with` |

**R-16 meta-control**, added inside `self_test()` right after control #9 is appended (not one of
the nine — it runs `expect_trip(..., quiet=True)` directly and `sys.exit`s by hand if either
probe is wrongly accepted, so it cannot inflate `trips`/`len(controls)`): using control #8's own
`because` (`flag_typo_because`), it asserts that swapping the real callback for
`lambda: sys.exit("unrelated parser failure")` is REJECTED, and separately that
`lambda: sys.exit(0)` is REJECTED. This is exactly the review's two perturbations (finding 9 /
`wave1-codex-verify.md` §9), reused as the permanent regression guard rather than thrown away.

## 2. The red-once line

Reverting `expect_trip`'s body to the pre-fix shape (`except SystemExit as trip: return 1`,
signature otherwise kept) while leaving everything else untouched turns `--self-test` red: the
R-16 meta-control's first probe (the unrelated-diagnostic swap) is silently accepted by the
reverted function, and the meta-control's own `sys.exit` fires —
`"expect_trip counted an UNRELATED SystemExit as the flag-typo guard's own trip - finding 9 / R-16
is back"` — nonzero exit, confirmed with an `if`/`else` control-flow check (not `$?`, which this
WSL shell does not propagate reliably through a chained `bash -lc '...; echo $?'`; `if cmd; then
... else ... fi` was used throughout for every pass/fail check in this round). Restoring the fix
turns it back to green with no other change.
