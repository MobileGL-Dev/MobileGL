## 2. THE STAMP RULE — v1 reads this section

`Server/PipeApplier::StampVerbBoundary(MGPWireOp op)` should be exactly:

```cpp
void PipeApplier::StampVerbBoundary(MG_Pipe::MGPWireOp op) {
    const MG_Pipe::MGPipeVerb verb = MG_Pipe::MGPipeVerbForWireOp(op);
    if (verb == MG_Pipe::MGPipeVerb::kVerbCount) return;   // not a verb boundary: stamp nothing
    MG_Pipe::MGPipeServerStampVerbBoundary(verb);
}

Uint64 PipeApplier::ResidualPullCount() const { return MG_Pipe::MGPipeResidualPullCount(); }
```

Both entry points are declared in `MG_Backend/MGPipe/PipeInputs.h` under
`#if MOBILEGL_BUILD_DISAGGREGATED` and defined in `PipeInputs.cpp`.

**WHEN.** Once per record, **before** the record's applier runs, exactly as
`PipeApplier.h` already says. `MGPipeVerbForWireOp` is generated from
`MGP_VERB_OP_LIST` in `FieldOwnership.def` and answers `kVerbCount` for every op that is not a
verb boundary, so calling it unconditionally on every record is correct and cheap.

**WHICH OPS.** Four: `Clear → Clear`, `DrawVbo → DrawArrays`, `ReadPixels → ReadPixels`,
`Blit → BlitFramebuffer`. The two name spaces do not line up by name, which is why the map is a
table and is checked against `PipeCalls.def` and `FillPoints.def`.

**`Present` IS DELIBERATELY NOT A STAMP POINT**, although CONTRACT §7 puts it in class B:
`FillPoints.def:21` — *"Present and SetSwapInterval go through BackendObject virtuals and read no
frontend state, so they are not verbs here"*. There is no `MGPipeVerb::Present`,
`MGPipeValidateForVerb` is never called for it, and stamping there would retire the previous
verb's answers with nothing to put in their place. Pinned by
`VerbBoundaryOpsAreTheFourTheStampRuleNames`.

**WHAT IT DOES**, in three lines, the third being the load-bearing one:

1. `++CurrentVerbSerial` and set `m_currentVerb`, so a Fatal names the verb instead of `<none>`;
2. **stamp** `FilledGen[i] = CurrentVerbSerial` for every field that is (RECORD-SUPPLIED or
   APPLIER-DERIVED) **and** in this verb's `kMGPipeClassFieldMask`;
3. **zero** `FilledGen[i]` for everything else — BARRIER-PULLED, FATAL, and anything outside the
   class mask.

(3) is what makes the instrumentation real. The client's residual fill stamps **all 63** fields at
its own verb boundary, so without the withdrawal every field would read fresh on the server, `rsp`
would be identically 0, and the exit gate would be decoration — the exact "an inproc
implementation proves nothing" failure R-2 exists to prevent. It is also, for free, what cancels
the sticky exemption.

The value a BARRIER-PULLED read then gets is still the client's residual fill's, and it is still
**correct**, because the verb barrier (R-1) leaves exactly one of the two threads runnable. That
is the debt, not a bug.

**CLEARING.** `MGPipeServerClearVerbBoundary()` disarms it. The client's own
`MGPipeValidateForVerb` and `MGPipeLeaveVerb` already call it (landed here), so v1 does **not**
have to — but calling it when the apply thread leaves the applier is harmless and makes the flag
mean "the current stamps are the server's" even if a future phase stops routing through the
client's fill.

**WHAT V1 MUST NOT DO.** Do not stamp per record on non-verb ops (a `set_dynamic_state` between
two draws is part of the draw's verb); do not batch two verbs into one stamp (the withdrawal is
per verb and a batched stamp would let the second verb read the first's answers).

## 5. Findings

**F-1. Every backend read of the pixel store passes `false`.** All six
`MGB_CTX->GetPixelStoreParameters(...)` sites in the tree read the PACK half:
`DirectGLES.cpp:7924`, `:9399`, `:10893`, `:11272`, `Utils.cpp:2302` and
`VulkanRenderer.cpp:10980` — **six, not the five the contract names**; the scout named five and
did not open them. `PipeFill.cpp`'s `EmitPixelPackState` says the same from the other side:
*"PACK only, deliberately: nothing on the far side of the boundary reads unpack state"*. So the
unpack half is not merely uncarried — **it has no reader at all**, which is what makes FATAL the
right class for it rather than BARRIER-PULLED.

**F-2. RECORD-SUPPLIED is 32, not 31** (§1.2).

**F-3. The applier's derivation and the record-supplied set overlap completely.** The contract
describes APPLIER-DERIVED as "the render-state mirrors, `m_pixelStore[0]`, capability bits, the
current vertex attribute and the patch fields", but all of those except the pixel store are
*also* emitted, and `GetCurrentVertexAttribute` is emitted-and-still-pulled (the applier writes it
and cannot reproduce GLContext's cross-view conversion — `PipeFill.cpp:1884-1896`), so it is
BARRIER-PULLED, exactly as the contract's own 21-row list says. With "each row in exactly one
class" enforced, APPLIER-DERIVED has precisely one member: the field with a record that supplies
*half* of it. That is a real class, not a degenerate one — it is the shape "a record arrives and
the applier writes the field, but no row of the emitted list may claim it".

**F-4. `Present` is class B but not a verb** (§2).

## 6. Where I did not do what the contract said, with evidence

### 6.1 `GetPixelStoreParameters` is split BY ARGUMENT, not into a second field id

The contract (§3) and the brief (R-7, §5 p1) both say: split it into pack and unpack field ids,
`kMGPipeInputFieldCount` 63 → 64. **I did not**, and the table narrows it by argument instead —
one field row (`APPLIER_DERIVED`) plus one row in `MGP_FIELD_OWNERSHIP_ARG_LIST`
(`arg0 == 1 → FATAL`), consulted by the accessor through `MGP_INPUT_CHECK_ARG`.

Four reasons, in order of weight:

1. **The tree already ruled this exact shape, in the file the contract cites.**
   `Coverage.def:62-69`, about `GetBufferBindingSlot`: *"THE ROW STAYS ONE ROW, and that is
   structural rather than a shortcut: this list IS the `MGPipeInputField` enum and the
   `PipeInputs` field set, and the field is ONE array … that a second row of the same name could
   only duplicate."* `m_pixelStore[2]` indexed by `isUnpack` is the same shape as
   `m_bufferBindingSlot[15]` indexed by a `BufferTarget`, and `GetBufferBindingSlot` is
   half-migrated in exactly the same way (8 of 15 targets carried, 7 not) without anyone
   proposing 15 field ids for it.
   **The same file also says the opposite about *this* field**, eleven lines down
   (`Coverage.def:173-181`): *"**Until the field is split**, the whole of it keeps going through
   the fill loop and the pack half is simply written twice."* So the precedent is genuinely
   two-sided and v1 of this report presented only the half that supported the decision
   (reviewer's q-3). What settles it for P5 is reason 4, not the precedent: the tree anticipates
   a split into two *storage* halves so that each can be independently filled and verified, and
   this package needed a split into two *verdicts*, which is a smaller thing and is available
   without a field id.
2. **A second field id costs c0's files and mine cannot.** The enum is generated from
   `Coverage.def`'s accessor list; the class masks come from `FillPoints.def`. Both are c0's,
   `gen_pipe.py` is c0's, and the preamble's 铁律 is that a package does not edit another's files.
   The argument-keyed form needed **zero** c0-owned files.
3. **It would break the strangler invariant.** `PipeInputs.h:140-142`: *"every accessor keeps the
   NAME, PARAMETERS and RETURN TYPE of its GLContext counterpart … so the strangler sed is
   type-neutral"*. `GLContext::GetPixelStoreParameters(Bool isUnpack)` is one accessor; two field
   ids want two accessors or a field id chosen from an argument anyway — and if it is chosen from
   an argument, the second id buys nothing the argument row does not.
4. **The result is strictly stronger than the contract's.** Two field ids would make the unpack
   half BARRIER-PULLED — counted and *silently served* out of the client's fill. Because no
   backend reads it (F-1), FATAL is available, and a future reader gets a named abort on its first
   read instead of a stale struct. `TheUnpackHalfOfThePixelStoreAbortsWhileThePackHalfDoesNot`
   pins both halves.

**What would overturn it:** a decision by the integrator that the 63 → 64 move is wanted anyway
(e.g. because the verify comparator or a later phase needs per-half stamping). The change is then
small and localised: add `GetPixelStoreUnpackParameters` to `Coverage.def`'s accessor list and to
`FillPoints.def`'s `kReadback`/`kTextureOp` rows, add its storage row to
`MGP_INPUT_STORAGE_LIST`, and replace the one row in `MGP_FIELD_OWNERSHIP_ARG_LIST` with a normal
field row. I did not pre-stage it because it would have left c0's files edited by p1.

Consequently **`kMGPipeInputFieldCount` stays 63** and there were no asserts to move. The two
stale doc lines the package was asked to fix were stale for a different reason — they said
**61** — and both are corrected to 63 (`ARCHITECTURE.md:83`, `MEASUREMENTS.md:82`).

### 6.2 `InvalidateCompileEnv` is BARRIER-PULLED with retiring phase "P5"

The contract lists the seven sticky forwards' P5 assignment as "five → BARRIER-PULLED,
`InvalidateCompileEnv` → `OnCapsInvalidated`, `RecordError` → BARRIER-PULLED". There is no fifth
class, and R-7.1 requires every row to be in exactly one of four. So `InvalidateCompileEnv` is
**BARRIER-PULLED, retiring in P5**, and `OnCapsInvalidated` is recorded as its *mechanism* in the
forward row (`kMGPipeFieldOwnershipForwardMechanism`). It is the only row in the table whose
retiring phase is P5 itself. Nothing about the runtime behaviour differs from the contract's
intent: it is counted in `rsp` and `Fatal` under strict, and it stops being either the moment
R-12's reverse channel replaces the forward.

### 6.3 `PipeFilled.inc:421` is not edited

The contract asks that the unconditional-fresh line stop being unconditional in a split build.
It is **generated by `gen_pipe.py`**, which is c0's, and editing it there would change
`MGPipeInputFieldIsFresh` for every push build. It is also unnecessary: `:420`'s
`gen == 0 ⇒ not fresh` is tested **first**, so the stamp's withdrawal already wins. Pinned by
`TheStickyExemptionIsCancelledByTheServerStamp`, which shows the seven fresh after a client fill
and stale after a server stamp. **What would overturn it:** a phase that wants the seven poisoned
*without* a server stamp having happened — at which point the line has to move, in c0's file.

## 7.2 The other MAJORs

### M-4 — the stamp asserts freshness from the table, not from the records that arrived

**Not changed. Documented — and the reviewer's proposed repair does not work as stated**, which is
the useful half of this answer.

The finding is right: for the 33 RECORD-SUPPLIED + APPLIER-DERIVED fields, a dropped emitter or an
over-eager suppressor now renders wrong instead of aborting, and the report did not say so.

The suggested repair — *"have `MGPipeApplyAccess`'s writers stamp the field they write, and let
the verb boundary only withdraw"* — would abort on nearly every verb. `MGPipeInputFieldIsFresh`
requires `gen == CurrentVerbSerial` for a non-sticky field, and the applier's mirror is
**persistent across verbs by design**: `bind_render_state` / `set_dynamic_state` /
`set_sampler_views` are all suppressed when nothing changed (`PipeFill.cpp:1917-1923`), so a field
written at verb N and legitimately not rewritten at verb N+1 would carry stamp N, read stale and
Fatal. The client's fill does not have this problem because it copies **every** field in the class
mask at **every** verb; the applier structurally cannot.

So the real choice is between three designs, and it needs a **c0 ruling**, because two of them
change `MGPipeInputFieldIsFresh`, which `gen_pipe.py` generates:

| | rule | catches a dropped emitter? | cost |
|---|---|---|---|
| **A (landed)** | the boundary stamps by class + mask | no | 0 |
| **B** | writers stamp; the boundary stamps a supplied/derived field **only if it already has a non-zero generation** | yes, for a field whose record *never* arrives | one call per applier write site in `PipeApply.cpp` (w1-shared): 6 sites + `MGPipeDeriveRenderStateFields`' 29 fields |
| **C** | writers stamp; supplied/derived become *server-sticky* (`gen != 0 ⇒ fresh`) and the boundary withdraws only the other two classes | yes, same scope as B, and it is the honest generation model for a mirror that persists | B's cost **plus** a change to `MGPipeInputFieldIsFresh` in `gen_pipe.py` |

Neither B nor C catches the case the reviewer names first — *a chunk dropped from a record that
does arrive* — because the write site still runs. That case's oracle is the verify lane's
compare-at-read, which is what `MOBILEGL_PIPE_VERIFY` is for and which does not exist under split;
saying so is more useful than implying a stamp could cover it.

**Recommendation: C, in a later round or a later phase, not mid-flight.** It touches a c0 file and
a w1 file and it changes the rule v1 is coding against *now*. Landing A and writing this table
down is the smaller risk. The integrator should rule before v1 places the call if they disagree.
