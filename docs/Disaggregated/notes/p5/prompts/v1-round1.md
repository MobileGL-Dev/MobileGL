# What you build

1. **`ServerLoop` + the `mgl-srv-apply` thread.** No `mgl-srv-io` in P5 — inproc's control plane is in the same process; P6 splits it. Park through `Doorbell::Wait(control.consumerParked, …, kWaitForever)` and treat `Wait == false && Dead()` as shutdown. **`CondVarDoorbell::Kill()` is the only thing that can un-park a `kWaitForever` waiter**: a parked thread never killed hangs `Shutdown`; one killed but not joined returns into memory the client has freed. Bind the thread with `MOBILEGL_IPC_SERVER_AFFINITY` (default auto, reuse `ShaderCompilePool`'s big-core probe) and **log the resolved mask**.
2. **The EGL context migration — the part that can sink the phase.** The server role privately holds a `BackendObject_DirectGLES`; the apply thread runs `eglMakeCurrent` **once** and holds the context for life, so `g_backendContextOwnerThread` is written once, `DirectGLES.cpp:11933-11953`'s six cache invalidations become a one-off, and the **16** `IsBackendContextCurrentOnThisThread()` sites in `DirectGLES.cpp` plus the 16 `CanTouchGLNow()` sites in `Managers.cpp` answer *true on the server* instead of silently degrading. The client's EGL lifecycle calls (`InitializeEGLDisplay`, `CreateEGLWindowSurface`, `MakeEGLCurrent`, `SwapEGLBuffers`, `SetEGLSwapInterval`, `ReleaseEGLSurface`, `ReleaseEGLResources`) become **blocking** control requests executed on the apply thread. `ReleaseEGLResources` and `~BackendObject_DirectGLES` **must** block, or `MobileGL::Destroy()` proceeds while the server still holds the context.
3. **The `Init.cpp` hook** at `MG_Backend/Init.cpp:50`, before the `switch`. Note `:43-44` also fills `gBackendFunctionsTable` from the object — that table is c1's emit table, so coordinate rather than inventing one.
4. **`Server/PipeApplier`**: drive w1's decoder into the existing `MGPipeApply*` free functions; `ApplyOne` = decode → stamp → apply → reply → advance `appliedSeq` by **one**. `appliedSeq` has exactly one writer, s1's `SessionConsumer::ApplyOne` — drive it, do not poke `RingControl` yourself. **The 64-record batching is banned while the verb barrier exists.**
5. **p1's stamp rule, exactly as p1 specified it** (`~/w7/notes/p5/p5-results/p1-v1.md`; its §7 supersedes parts of its own §2, so read §7): `StampVerbBoundary(op)` → `MGPipeVerbForWireOp(op)`, `kVerbCount` ⇒ stamp nothing; otherwise call `MG_Pipe::MGPipeServerStampVerbBoundary(verb)` once per record **before** its applier. It bumps the serial, stamps the verb class mask's supplied/derived fields and **zeroes everything else** — the zeroing is load-bearing, because the client stamps all 63 and without it `rsp` is identically zero. Four boundary ops: `Clear`, `DrawVbo`, `ReadPixels`, `Blit`; **`Present` is not one**. Two things p1 flagged for you: **`MGPipeServerClearVerbBoundary()` is MANDATORY on leaving the applier** (without it a spawned server latches the stamp for life and the sticky-exemption cases start aborting under strict), and **`PipeApplier::m_residualPulls` is vestigial — delete the member** rather than wiring both it and the process-wide counter.
