## 2. 关键事实（实现中发现，计划里没有或有误）

- **bit 4 不能退役**：它同时门控 P5c rv 的 `set_context_values`。W3c 只删 ResidualValueBlock，bit 4 仍固定开。
- **不需要控制面修订号 +1**：删结构后 `kMGPipeWireCatalogueDigest` 变化，wireFingerprint 随之变化，新旧端按名拒绝。
- **CMake 旧缓存**：`MOBILEGL_PIPE_PUSH=OFF` / `MOBILEGL_PIPE_LEGACY_MEMOS=ON` 在旧构建树（含 FCL 的 Gradle `.cxx`）里是默认值，所以是 WARNING + 忽略，不是 FATAL。
- **位图固定开（ID-P13-3）在 W3b 落地**：`ConfigLoader` 对清 bit 0-13 的掩码 `Fatal{PipeSubsystemsFixedOn}` + abort；Off / Refused 车道改为 `DirectGLES.SubsystemMaskRefusal.<Lane>` 具名拒绝对照（`Harness/RefusedMaskControl.cmake`，读日志确认原因）。各解析函数里 `legacyMemosEnabled` 改为常量 `true`，只为单元测试的掩码扫描不 abort；这些分支 W6 删。
- **monolith 仍走借用槽位的单元列表**（`UnitTexturesByHandle()` 在 monolith 为 false）——这是 W4c 要换的。`UnitMemoRefusesToDriveATwinFromAnotherTexture` 恢复并钉 P2 掩码（单元车道没有 P4a consumer，0x3fff 下建不出记录）；红检已做（见 ci-cleanup-log）。
- **单元车道无法创建纹理记录**（`NoP4aConsumer`），任何需要纹理记录的白盒单元用例都要放到集成层。
- **本地 CMake 必须 3.31.10**：CMake 4.x 下 gtest 的 ENVIRONMENT 列表转义不同，集成用例把 `MOBILEGL_BACKEND_TYPE=DirectGLES;__EGL_VENDOR...` 当成一个变量，全部假红。

## 3b. W4 设计要点（W4a 落地时的实际做法）

- **谓词**：`MG_Config::DataArmIsRecord()` / `RecordArmAliasesFrontend()`（`Config.h`）。monolith 的 `MonolithTakesRecordArm` 由 `MOBILEGL_PIPE_DATA_ARM`（默认 `record`，W4-W6 专用）且后端为 DirectGLES 时才为真；Magma 在其一次性换臂时加入。无 MG_Remote 构建恒 false（W5 改）。
- **三类分支**：K（生命周期、角色、caps 来源、传输层级）留 `Transport`；F（数据臂）改谓词；S（store 是否复制）问 `CopiesIntoServerStorage()`——`M:3910` 那处若误用谓词会把所有别名基址清空。
- **verb 端口**（`EmitTables.cpp`「THE MONOLITH VERB PORT」）：monolith 下被端口接管的槽位跑 EmitTables 的同一套规划与 pre-verb 钩子，再把记录交给进程内 `ServerVerbSink`（它写 `VerbIndirectBuffer` 等并调真表）。由 `MobileGL/Init.cpp`（SHARED）安装，不由 `MG_Backend/Init.cpp` 装——后者是 server 对象，装会让链接棘轮报新前端引用。W4a 端口槽位：20 个 draw + 2 个 dispatch。后续波把新 verb 同时加进 `InstallMonolithVerbPort` 与 `ApplyOnMonolithPort` 的 switch。
- **§1.4 别名刷新**：`RefreshAliasedStoreFromGpu`（`Managers.cpp`）：读回 GL buffer → `OnBufferWriteback`（前端把字节拷进它的影子，即别名基址）→ 清 `serverGpuWritten`、盖 serial、bump epoch。前提：monolith 记录臂在 sub-data 与 respecify 时就铸 twin；孤立 respecify 也带影子基址（上传仍按描述符的 `HasDefinedContent` 门控）；`contentSinceRespecify` 代替别名 store 没有的覆盖集回答流式写法。
- **GPU 写标记**：`GpuWriteSetIsClientSide()` 改谓词，client 侧的保守集由端口的 `MarkGpuWritesForDraw` 打；后端只标自己的 twin（`serverGpuWritten`）。image 单元仍在前端臂（W4c），其 buffer-texture 写在前端臂里额外标 twin。
- **单元测试**：`BufferTest` 三例断言前端臂的 map 推送，钉 `ScopedMonolithFrontendArm`，W6 随前端臂删。
- **W6 待办（monolith 登记的余项）**：`F1WireScenario` 在 `SetUp` 用 `SplitRuntimeSkipReason()` 整组跳过 monolith，所以 Magma 的 `MGITEST_MAGMA_FORCE_SHADER_MIPMAP` 车道（`ShaderMip1/2.`、`DepthMip.`）还没有 monolith 登记；它的断言读 `emitSeq`（编码器序号），monolith 记录臂走路由表不经编码器。W6 删前端臂时把 F1 的门改成「记录臂」并换掉 `emitSeq` 证据，再补 monolith 登记、退役对应的 census 跳过。
- **Magma 换臂**（同一会话稍后）：一次性；`MonolithTakesRecordArm` 对两后端都为真。坑：服务端产生的字节（回读落入 pack buffer 的 `LandReadbackInBuffer`、纹理重铸 / 再生成的 `Adopt`）绝不能被别名 store 当基址——缓冲侧用 `MGPipeServerOriginatedWriteScope` 走「直接上传 GL + 标 GPU 写」，纹理侧 `Adopt*` 默认复制、只有客户端记录的 run 传 `frontendShadow=true`（曾造成 use-after-free：重铸后首 16 字节是 malloc 元数据）。
- **本机 retrace**：`~/mgl-p13-tools/sync.sh` 才物化 LFS fixture（`sb.sh` 用的 `sync2.sh` 会把它们复原为指针）；跑前设 `MOBILEGL_GPU_HANG_BUDGET_MS=0`。
- 完整的 site 分类表与后续步骤（W4b 纹理别名 store、W4c、Magma）见 Plan 代理的设计（会话 scratchpad `W4-design.md`；要点已并入本节）。

## 3c. W5 要点（记录臂移出 MG_Remote，S7 已翻转）

- **形态**：`MOBILEGL_BUILD_RECORD_ARM` 是普通 CMake 变量，S7 起恒 ON（S8 unifdef 掉）。push 库（无 MG_Remote，FCL 形态）现在跑记录臂：`runtime_mode_proof` 要两形态都有 `MG_Record` 符号（push 294 / split 300），push 仍 0 个 `MG_Remote`。
- **代码位置**（命名空间 `MG_Record`）：暂存库 `MG_Backend/Record/`；`RecordVerbSink`（记录动词的服务端半边，`ServerVerbSink` 继承它）；动词发射器 + monolith 动词端口 + GPU 写集合 `MG_Impl/Pipe/Verb/`；持久映射跟踪器 `MG_State/GLState/BufferState/`。跨层只经缝：`MG_Pipe/PipeSessionFail.h`（`MGPipeRecordFail/Latch/Latched`，`FatalFunnel.cpp` 静态注册）、`PipeClientSeam.h`（设备丢失 / 拒绝后确认丢失）、`MG_Backend/Record/ApplyRoleBackend.h`、`VerbPort.h` 的 `VerbSession` 解析器（`EmitTables.cpp` 静态安装）。include-closure 的 `record-core` 探针守住它们不碰 `MG_Remote/` 与 flatbuffers。
- **翻转后的教训**：试翻转「能链接」不等于「行为相同」——split 里的 monolith 记录臂跑过的很多块仍挂在 DISAGG 上，push 编进了谓词却漏了消费者，结果是 Magma 析构崩（wire store 没在 VMA 之前清）、Espryt 读回 ERROR（记录动词的 verb 状态盖章没编进来）。办法：`scratchpad/suspects.py` 扫「DISAGG 块里出现记录臂机制」的块，逐个判；然后用 push 的 unit + integration-gpu + verify 树三套跑到绿。还剩的 DISAGG 块（约 300）都是传输本身：会话、共享图像、T0、设备丢失闩、角色拆分、caps 来源、EGL 服务端窗口。
- **verify 树第一次跑 monolith 记录臂**：监视读钩子在端口的中性 pack 窗口里改用已应用的 pack（`MonolithPortApplyingForVerify()`）；monolith 的 poison-omission 对照改省略 `ReadPixels:GetPixelStoreParameters`（记录臂不再读 `GetActiveTextureUnit@GenerateMipmap`）。
- **FCL 开关**：`MOBILEGL_PIPE_PERSISTENT_MPROTECT=0` 不装跟踪器的 SIGSEGV 处理器（JVM 隐式空指针检查也用 SIGSEGV，处理器按设计链式转交，但从未在 HotSpot 里跑过）。设备上 FCL 冒烟仍是延后检查项。
- **剩余**：S8（unifdef 掉 `RECORD_ARM`、`!RECORD_ARM` 臂、`retired_switches` 规则、`wire_declines_audit` 回到单守卫）；测试文件里仍有 DISAGG 守卫的记录臂用例（`SplitBufferTest` 等）随 S8 / W6 处理。
