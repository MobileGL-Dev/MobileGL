## 2. 关键事实（实现中发现，计划里没有或有误）

- **bit 4 不能退役**：它同时门控 P5c rv 的 `set_context_values`。W3c 只删 ResidualValueBlock，bit 4 仍固定开。
- **不需要控制面修订号 +1**：删结构后 `kMGPipeWireCatalogueDigest` 变化，wireFingerprint 随之变化，新旧端按名拒绝。
- **CMake 旧缓存**：`MOBILEGL_PIPE_PUSH=OFF` / `MOBILEGL_PIPE_LEGACY_MEMOS=ON` 在旧构建树（含 FCL 的 Gradle `.cxx`）里是默认值，所以是 WARNING + 忽略，不是 FATAL。
- **位图固定开（ID-P13-3）在 W3b 落地**：`ConfigLoader` 对清 bit 0-13 的掩码 `Fatal{PipeSubsystemsFixedOn}` + abort；Off / Refused 车道改为 `DirectGLES.SubsystemMaskRefusal.<Lane>` 具名拒绝对照（`Harness/RefusedMaskControl.cmake`，读日志确认原因）。各解析函数里 `legacyMemosEnabled` 改为常量 `true`，只为单元测试的掩码扫描不 abort；这些分支 W6 删。
- **monolith 仍走借用槽位的单元列表**（`UnitTexturesByHandle()` 在 monolith 为 false）——这是 W4c 要换的。`UnitMemoRefusesToDriveATwinFromAnotherTexture` 恢复并钉 P2 掩码（单元车道没有 P4a consumer，0x3fff 下建不出记录）；红检已做（见 ci-cleanup-log）。
- **单元车道无法创建纹理记录**（`NoP4aConsumer`），任何需要纹理记录的白盒单元用例都要放到集成层。
- **本地 CMake 必须 3.31.10**：CMake 4.x 下 gtest 的 ENVIRONMENT 列表转义不同，集成用例把 `MOBILEGL_BACKEND_TYPE=DirectGLES;__EGL_VENDOR...` 当成一个变量，全部假红。

## 3. 本地环境（WSL archlinux）

- `~/mgl-p13-src`：从主仓库克隆的 LF 工作副本（`origin` = Windows 主仓库，分支 `p13`），子模块从主仓库本地拉。`~/mgl-p13-tools/sync.sh` 同步到 `p13` 已提交状态并从主仓库工作区按 sha256 物化 LFS fixture（有 29 个缺）。apitrace 子模块的第三方子模块已 `--depth 1` 拉过；glslang External 用 `update_glslang_sources.py` 拉过。
- 构建：`~/mgl-p13-tools/build_split.sh`（`~/mgl-p13-split` + `~/mgl-p13-retrace`），`build_push.sh`（`~/mgl-p13-push`，FCL 形态），`itest.sh <build> <tag>`（CI 同款 integration-gpu）。PATH 前置 `~/mgl-p13-tools/venv/bin`（CMake 3.31.10）。
- 经验：WSL 命令一律写成脚本文件再 `MSYS_NO_PATHCONV=1 wsl -d archlinux -- bash <file>`，`bash -lc '...'` 的引号与 `$` 会被吃；Git Bash 的 heredoc 会吃掉反斜杠，Python 编辑脚本用 Write 工具写文件再运行。
- 工具：scratchpad 下 `pyunifdef.py`（W3b 用的部分求值器）、`retire_names.py`（从普查基线退役具名用例）。
- `~/mgl-p13-apitrace`：apitrace CLI（`apitrace dump`）。
