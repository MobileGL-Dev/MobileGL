## 4. Rulings I made, each with what would overturn it

1. **The handles are LOOKED UP, never minted.** `MGPImageBind::Res`, `MGPCopyRegion::Src/Dst`,
   `MGPStorageBlockBinding::ShaderCso` and `MGPGridInfo::IndirectBuffer` come from
   `MGPipeSlots().FindByLifetimeId(...)`, not `Acquire(...)`. Every one of these sinks
   dispatches on the GL NAME — that is what rule D carries it for — so the handle is for P7.
   `Acquire` would MINT a slot at a call site that emits no create record, handing the server an
   identity it has never seen; a null field is the true statement "no handle published yet".
   *Overturned by* P7 dispatching on `Res` instead of `GlName`, which needs the minting form
   plus an ordering guarantee this row does not have.
2. **Only the two dispatch slots carry a pre-verb hook.** b1's hooks describe "the work the
   record is about to start". A bind, a barrier, an image copy and a block rebinding start no
   shader and read no mapped buffer; the dispatch that later reads the image is the verb that
   carries both hooks. Running them on all seven would push the same maps several times per
   dispatch and inflate b1's per-row counters. *Overturned by* a measured workload whose
   coherent-map write is read by a copy or a barrier with no dispatch between.
3. **The renderbuffer endpoint is refused on BOTH sides of the wire.** The client refuses before
   emission (ID-57's shape, so the census greps it where the other client refusals are) and the
   sink refuses a record that names `GL_RENDERBUFFER` in either target. *Overturned by* a
   renderbuffer sticky forward or P7's handle keying.
4. **A copy whose GL name no longer resolves DECLINES, it does not Fatal.** `OnResourceCopyRegion`
   logs once and returns false — the monolith's own answer in its own words
   (`DirectGLES.cpp:9067`, "declining the copy"); the frontend validator is what keeps it
   unreachable and what reports the `INVALID_VALUE` the application is owed. *Overturned by* a
   measured entry that reaches it, which would mean a pull went stale under the barrier.
5. **The atomic-counter barrier lowering stays in the backend.** `OnMemoryBarrier` forwards
   `Bits` untouched. Espryt's "counter bit implies storage bit" is a statement about the driver
   (`DirectGLES.cpp:8837`); repeating it client-side would make the split arm and the monolith
   arm two different calls. *Overturned by* nothing in P5b.

### 4.2 The ruling I was asked to make, and the measurement that changes its JUSTIFICATION

Contract §6.7 rules the mirror skipped under split and says **"what the skip loses is bounded by
two Fatals"**. I implemented the skip. The bound is **half right, and I measured both halves**:

- The `texture-remint-pull` half is real: 46 entries reach it, by name (§3.1).
- **The `glGetTexImage` half does not hold, and the skip is not what breaks those entries
  anyway.** I ran the experiment: with the skip compiled out (`if (false && …)`, rebuilt,
  re-run) the five DirectGLES packed-readback entries —
  `CopyImagePacked16Scenario.{Array,Flat}…` ×2, `WidenedPacked16` ×2,
  `PackedWordReadbackScenario.ACopiedRgb9E5Word…` — **fail identically**. So i1's mirror skip
  costs the lane exactly the 46 named aborts and nothing else.
- What actually breaks those five is `glGetTexImage` under split: `GetTexImage_State`
  (`GL_Texture.cpp:5331`) rejects with `GL_INVALID_OPERATION` and returns BEFORE
  `GetTexImage_Backend`, so the class-C `Fatal{UnmigratedVerb, "GetTexImage"}` never fires and
  the caller keeps its zero-filled buffer. The scenario reads the zeros as texels.
  **A class-C slot that silently answers nothing instead of refusing by name is the one shape
  ID-47 says a picture comparison cannot see**, and it is worth the integrator's attention
  independently of i1 — it is wave-3 / P9 territory.

*What would overturn the skip itself:* nothing i1 measured. If the integrator wants the honest
alternative anyway, it is one line — delete the `#if MOBILEGL_BUILD_DISAGGREGATED` early return
and those 46 entries go back to aborting `Fatal{UnmigratedEmulation, "copy-image-shadow-mirror"}`
by name instead of proceeding. That trades 46 named aborts for 46 entries that get further.

### 4.3 The 89 wrong-answer failures, and why i1 does not believe they are i1's

**82 of 89 are DirectVulkan (Magma); 7 are DirectGLES (Espryt).** The load-bearing observation
is that **the same scenarios pass on Espryt and fail on Magma from the same wire records** —
`DoublePrecisionScenario` 7/7 pass on DirectGLES and 7/7 fail on DirectVulkan, and so do
`AtomicCounterScenario`, `SsboArrayLengthScenario`, `UniformInitializerScenario` and
`ProgramPipelineScenario`. The record is backend-agnostic; only the backend differs.

The Magma shape is uniform: the compute dispatch runs, no server-side error is logged, and the
SSBO the shader writes reads back all zeros
(`DirectVulkan.DoublePrecisionScenario.ADoubleUniformKeepsItsDeclaredInitializer`: `values[0]`
is 0, 2.5 expected). Magma registers a real `DispatchCompute` slot, so the sink is calling it;
what is missing is inside `VulkanRenderer::DispatchCompute`'s own state resolution under split.
**Magma's split compute/image path is the next round's package, and it is the single biggest
item i1 hands on.**

The 7 DirectGLES failures: 5 are the `glGetTexImage` shape of §4.2; the other two are
`TextureParamsWithoutASamplerViewScenario.ACopyImageEndpointOnlyTexturesParamsReachTheDriver`
(a white-box G9 case whose own message diagnoses it: "the record reached the server and the
server has not pushed it" — Espryt defers texture-param application to the first sampler view,
and a copy-image-only destination never gets one) and one
`ResourceSubsystemOff.LargeArenaAdoptionScenario…` entry that the runner classes `failed` while
its own output says `SKIPPED` ("runs only in its own lane") — a census-classifier artifact, not
a product failure.

## 5. What I believe the brief or the contract got wrong or left open

1. **The brief says 235 lane entries; it is 239.** 138 + 49 + 30 + 18 + 4. The four
   `ShaderStorageBlockBinding` entries are missing from the brief's arithmetic.
2. **Contract §6.7's "bounded by two Fatals" does not hold for the `glGetTexImage` half** —
   §4.2, with the experiment that shows it and the site that causes it.
3. **The census manifest is not a fixed 1149.** It is `ctest -L integration-gpu` on the tree
   under test, and every package that adds a split lane entry (which also carries
   `integration-gpu`) grows it. The four packages will each grow it; the diff has to be taken
   over the intersection, and c0b's 432/185/505/27 is a baseline for the COMMON entries only.
4. **A `DirectGLES.Split.` lane entry must emit a record** (`ScenarioFixture.h:86`), so a
   whole-scenario `TEST_FILTER` cannot be used for a scenario that has pure state cases:
   `ProgramPipelineScenario` has nine of them and they are red for having nothing to say. i1's
   block filters to `*StorageBlock*`. A package adding lane entries also has to extend
   `Harness/SplitLogPaths.cmake.in`, or `SplitLogPaths.PrivateAndDistinct` fails for the whole
   lane — that file's loop is a hard-coded list of TEST_LIST variables and every package needs a
   line in it.
5. **`FieldOwnershipTest` runs only in the split unit lane.** The three other unit lanes stay at
   1817 with an i1 case added to that file; worth knowing before someone expects 1818.
