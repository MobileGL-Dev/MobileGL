## 3. The three things the other packages most need to know

### (a) The naive "does MG_Remote/Client exist" probe ARMS AGAINST c0's STUBS, and it went green against monolith

This is measured, not predicted. The brief tells t1 to copy `mgl_itest_probe_for_symbol` and probe
for a **symbol**. That is necessary and it is **not sufficient on this tree**: package c0 already
landed `MG_Remote/Client/{CapsMirror,ClientSession,EmitTables}.{h,cpp}` and
`MG_Remote/Server/{PipeApplier,ServerLoop,ServerSession}.cpp` as SIGNATURE STUBS - every entry
point is `MGLOG_F("MGPipe: Fatal{Unimplemented..., \"...\"} - P5 package <x> has not landed this
yet; c0 shipped the signature only")` + `std::abort()`, `RemoteEmitTable()` aborts on sight and
`ImplementedVerbCount()` returns 0. A probe for `kRemoteEmitSlotCount|BackendObject_Remote|CapsMirror`
answered YES, the Split lanes armed, and eleven entries named `DirectGLES.Split.*` went **green
having run the monolith path end to end**.

The arming condition is now a conjunction with a **negative** half: the client names its own
symbols **and** no source under `MG_Remote/Client` or `MG_Remote/Server` still matches
`Fatal.Unimplemented`. That is layout-independent in the way the house rule demands - c1, s1 and
v1 have to delete those aborts to implement anything - and it arms itself on the commit that
removes the last one. **Whoever lands the last stub arms eleven ctest entries and two negative
controls in the same commit.** Configure prints which file still carries a stub.

### (b) SSIM cannot be the split retrace gate. A PULL library under `MOBILEGL_TRANSPORT=inproc` replays OpenRA at ssim=1.000

Measured twice, on both threading paths into `run_trace_case.cmake`. In a build without
`-DMOBILEGL_BUILD_DISAGGREGATED=ON` the whole `MOBILEGL_TRANSPORT` parser is compiled out
(CONTRACT-P5 §5), so the variable is accepted by the environment, steers nothing, and every frame
still matches its golden. There are now two guards and neither is the picture:

* **build-level** — `nm --defined-only libMobileGL.so | grep -i MG_Remote` non-empty, asserted in
  `build-linux-split`, in `retrace-split`'s library swap and in the gate's part 1;
* **run-level** — `run_trace_case.cmake` demands the library's own log carry
  `ConfigLoader`'s `MOBILEGL_TRANSPORT=inproc` INFO line, which exists only in a disaggregated
  build. Negative control: a pull library under `inproc` is **RED**, and the failure message names
  the transport rather than the picture. This is in the gate as a standing control.

Corollary for everyone: `MOBILEGL_LOG_ACTIVE_LEVEL` must admit INFO in every split lane, because
that one line is the only runtime evidence the transport resolved.

### (c) On llvmpipe the MONOLITH arm of `PersistentCoherentMapScenario` is the ADOPTED arm — so R-6 makes the split A/B a two-path comparison for buffers

Measured in `build-split` with the transport unset, in the window covering exactly the workload:

```
MGPipe stats: ... bytes/f[... pmap=0.00 ...] cso[csom=1 csob=1 mpr=1] ...
```

`mpr=1` (one acquisition attempt for one storage definition, as ARCHITECTURE.md:492 prices it) and

exit gate E3 run **different buffer code paths**, not the same path over a different transport,
and `mpr` is the only counter that is equal by construction. That is exactly why the counting
lanes are a PAIR that each assert the same constant rather than a cross-lane comparison.

**For b1 specifically** (all seven of your §4.1 items are reconciled in §2c above):

## 4. Decisions this package made that the brief and the contract did not

**D-1. `TriangleScenario`'s first case ends with `EndFrame()`, so `Present` is in target B's slot
set.** verb-census §B flags this as a choice to be made deliberately: the spec as written never
swaps, which would make B a strict subset of A minus `Present`. BRIEF §4.B lists `Present`(67)
among the catalogue rows B needs, so the frame boundary is in. Overturned by: a decision that B
should be the minimal draw and nothing else, in which case delete the trailing `EndFrame()` and B
drops to four slots.

**D-2. The split-lane skip guard lives in `ScenarioFixture.h`, not in the two new scenarios.** The
`Split.` family also points at `ClearThenReadPixelsScenario`, which is target A and predates P5 and
has no guard of its own; without this its five entries were the false greens of §3(a). One place
also means any later Split lane inherits it. The guard fires only when `MGITEST_SPLIT_LANE=1`,
which only the Split entries set, so the other ~1128 entries are untouched.

**D-3. The monolith lanes declare NO arm and RECORD it; only the split lane declares one.** Which
arm `AcquireMemoryRange` takes for a sub-16-MiB map is a property of the driver (llvmpipe mints; a
device may decline), so a monolith lane that pinned one would be red on hardware for a reason that
is not a defect. The value lands in the gtest XML as `persistent_map_arm`, so the recording is
machine-readable rather than a log line. The counting case also `SUCCEED()`s rather than skipping
when no arm is declared, because its `mpr` assertion is that lane's real claim and a skip would
have thrown it away with the arm.
Overturned by: a measurement showing every target device declines, in which case the monolith lanes
can declare `emulated` too and the A/B becomes a pure transport A/B.

**D-4. The trace-replay transport is threaded BOTH ways and asserted once.** `-DTRACE_TRANSPORT=`
(what the SPLIT variant passes) does `set(ENV{MOBILEGL_TRANSPORT})` at the top of
`run_trace_case.cmake`; the assertions at the bottom read `$ENV{MOBILEGL_TRANSPORT}`, so they fire
for the `-D` path and for a process-environment export alike. ARCHITECTURE.md:16 asks for the
former and BRIEF §5 for the latter; they are the same mechanism.

**D-5. `TRACE_OUTPUT_DIR` and `TRACE_ARTIFACT_DIR` carry the variant** (`OpenRA/DirectGLES-SPLIT`,
`OpenRA/actual-images-SPLIT`). `run_trace_case.cmake` `file(REMOVE_RECURSE)`s the output dir before
every run, so shared directories would mean the second arm erases the first arm's
`output/mobilegl.log` - and that log is the only valid refusal census, because the console sink is
compiled out of these configurations and `ctest -V`'s transcript is a false zero.

**D-6. `retrace-split` runs the UNCHANGED ctest names with the transport in the job environment,
not the `SPLIT` names.** `build-retrace` configures without `-DMOBILEGL_BUILD_DISAGGREGATED`, so
the variant entries are deliberately not registered there - a name that says SPLIT in a build that
cannot be one is worse than no name. The `SPLIT` name is registered, and verified to register and
to run, in a build that DOES have the option. See the debt in §6.

**D-7. The E1 and E3(a) negative controls are TWO-STATE, derived rather than assumed.** While the
Split entries skip, a "this step passes when ctest FAILS" control would be red for the whole of P5
for a reason that is not a defect. The expected state is read from the same fact the lanes read:
`MGITEST_REMOTE_CLIENT_PRESENT` appears in the generated ctest include files the artifact ships.
Armed → the knob must turn entries red; disarmed → the step says so loudly (`::warning` in CI, a
named line in the gate) and asserts nothing. It becomes a gate on the commit that lands the last
stub, with no edit.

**D-8. The gate hydrates fixtures from `~/w7/pipe` and never from GitHub.** A `git worktree add`
leaves 40 of the 41 fixtures as 130-byte LFS pointers (only `openra.tgz`'s object is in the local
cache), and a naive sweep then reports **"passed 2 / 79"**, which reads exactly like a
catastrophic regression. After copying from the integration tree - same commit, no network, files
marked `assume-unchanged` - the push sweep is **79 / 79**.

   Under inproc the two roles are two threads of one process, so `/proc` cannot separate them: the

   transport-resolution check lives in CI and in `run_trace_case.cmake`; a scenario-level arming
