## 2. The three traps, and where each is paid

1. **`GetRendererInfo()` returns a reference** (`BackendObject.h:590`) and `LogBackendInfo()` reads it at
   `MG_Backend/Init.cpp:21`, during `MG_Backend::Init()`, before any surface exists. `CapsMirror` owns a
   real `RendererInfo` and `BackendObject_Remote::GetRendererInfo()` forwards to it.
   **c0's stubs aborted on every accessor but `Valid()`/`Generation()`; that had to be reversed** — an
   abort there is not a stricter mirror, it is a process that cannot start. Every accessor now answers a
   placeholder *and logs one line naming itself*, so a wrong number that reached a caller announced itself.
   `MG_Backend::Init()` is **not** restructured (scout-caps-reply §1.2 (a)).
2. **`GetFormatCapabilities()` is non-virtual** (`:594`). `BackendObject_Remote` **fills**
   `m_formatCapabilities` through `MutableFormatCapabilities()`, driven by a new
   `CapsMirror::SetCapsAdoptedHook` — a raw function pointer, installed in the constructor, because the
   only moment the object can know to refill is when a snapshot lands, and the teardown path may not
   allocate (ID-8).
3. **`GetBackendType()` answers the server's backend.** No `Remote` enumerator exists and none was added;
   a snapshot naming a type this build has no enumerator for is **refused whole** rather than folded onto
   `Unknown`, because `GL_Framebuffer.cpp:47`, `GL_Texture.cpp:6536` and `CompileEnv.cpp:122` switch on it
   and take a wrong arm rather than failing.

## 3. The emit table

`kRemoteEmitSlotCount = 71`, and the partition is **arithmetic, not a comment**:

```
kUnmigratedSlots (= the X-macro's own row count + 3 hand-written) == 64
kLocallyAnsweredSlots + kEmittedSlots + kUnmigratedSlots == kRemoteEmitSlotCount   // static_assert
```

A slot that changes class without changing the arithmetic is a build break.

- **Class A (2):** `GetIntegeri_v` answers `MaxComputeWorkGroupCount` / `MaxComputeWorkGroupSize` from
  `MGPCaps::Dynamic`; any other indexed pname is a warn-once and **no answer**, because writing a wrong
  number is worse than leaving the frontend's own. `IsTimerQuerySupported` answers `kCapTimerQuery`.
  `PrefersCpuXfbPrimitiveAccounting` is not a slot and is answered from
  `kCapCpuXfbPrimitiveAccounting`.
- **Class B (5):** `Clear`, `DrawArrays`, `ReadPixels`, `BlitFramebuffer`, `Present`.
- **Class C (64):** the rest, including `SetSwapInterval`, `GetGpuTimestampNs` and the whole sync / query /
  XFB / compute / copy / mipmap surface.

**Class C is assigned FIRST in `BuildRemoteEmitTable`, deliberately.** If class B's assignment ran first,
a typo in the class-C list would leave a *null* slot — 91 potential null calls with no diagnostic. This
way the worst a mistake can do is name a verb that was meant to be emitted, loudly.

### Two record-shape decisions v1 and the integrator must ratify

- **`MGPClear::Kind`.** `MGPipeTypes.h:1273` states the list as a **comment** (`Whole | Color | Depth |
  Stencil | DepthStencil`) and mints no enumerator, because until now the record had no producer. c1
  defines `MGRemoteClearKind` in `EmitTables.h` with those five values in that order. **P5 only ever
  produces `kRemoteClearWhole`** — `glClear` is the only entry point that reaches the slot, the four
  `glClearBuffer*` and four `glClearNamedFramebuffer*` being class C — so `WireVerbSink::OnClear` should
  `Fatal` on anything else rather than guess. When the other eight migrate, this belongs in the contract.
- **`MGPClear::Fbo` and `MGPBlit::ReadFbo`/`DrawFbo` are the NULL handle, on purpose.** The bindings are
  `gPipeInputs`', written by the client's `MGP_FILL(Clear)` / `MGP_FILL(BlitFramebuffer)` immediately
  before the table call and held still by the barrier. Naming a handle in the record would be a *second*
  statement of the binding, and the second one is the one that goes stale.

## 4. The verb barrier

`ClientSession::EmitAndWait` composes s1's four primitives in the one legal order:

```
[assert the apply thread is not inside the applier]  -> EncodeRecord -> PublishAndNotify
  -> BarrierWaitScope + WaitForApplied -> DrainEventRing -> ReadReply
```

- **The wait and the reply's wait are one wait.** `kMGPipeCallFlagsFor(op) & kReplySlot` decides whether a
  reply is read — the catalogue, never the caller — so a caller that forgot to pass a buffer cannot turn
  an answer into a guess. **Acceptance is never re-derived and never assumed**: DECLINED is passed
  through as a real answer, and a `kReplySlot` row whose slot does not stamp its own seq is
  `Fatal{ReplyMissing}` rather than a plausible default.
- **`MOBILEGL_IPC_VERB_BARRIER=0` turns off the barrier and nothing else.** A reply-slot row still waits,
  because its answer is not derivable here and R-5 forbids inventing one.
- **The R-1 invariant is a runtime check now.** `InBarrierWait()` is `thread_local`; `ApplyThreadIsInsideApplier()`
  is a shared atomic. **v1 must bracket its `DecodeAndApply` with `ClientSession::ScopedApplierEntry`**
  (or the two `Note*` functions) or the check is inert — see §8.
- **The wait is bounded at 30 s** and its Fatal names the seq. A wedged CI job and a lost record look
  identical from outside and only one of them is a bug worth finding.
- **`SessionWait::ShutDown` is not a Fatal.** Teardown legitimately reaches it.
- **The reverse channel is drained here**, between the barrier and the reply read — the one instant at
  which the apply thread is known not to be inside the applier, and the thing that gives b1's
  `AwaitBufferWriteback` something to have waited *for*. `EventRingConsumer::Drained()` is called only
  after every popped payload pointer has been consumed (R-11 one level down).

## 5. R-8

`MGPipeResourceSubsystemEnabled()`, `P4aFamilyHasItsConsumer()` and `MGPipeResourceOpsHaveSubDataResident()`
now read the caps mirror when `MG_Config::Transport != Monolith`, and the op table otherwise. The third is
CONTRACT §7's third named capability probe and reads `kCapResidentSubData`.

All four P4a families ride the **one** resource consumer bit, exactly as they do in monolith — asking per
family would be a *new* rule, and a client that withheld more than the server refuses leaves the server's
handle arm live with no records to read.

**The negative control is counted, not inferred.** `CapsMirror::ServerConsumes` is R-8's only legal
spelling, so it counts its own refusals and names the family (`ConsumerRefusals()`,
`LastRefusedSubsystem()`, plus one warn line per family). "The client emitted nothing" and "nothing called
it" are otherwise the same observation.

**A placeholder mirror consumes nothing**, which is the safe direction: the legacy pull path runs. The
unsafe direction — emitting to a server with no consumer — is ID-39's 66 lost uploads.

### One test had to change, and the change IS the finding

`SanityTest.cpp`'s `DirectGLESBufferDrawProbe.UnderSplitTheRecordAloneAnswersTheLiveHostMapQuestion`
armed `MG_Config::Transport = InProcess` **and** `MGPipeSetResourceOps(&ops)` and expected the client gate
to answer from the op table. That is precisely the "right by accident under inproc" R-8 kills, and it went
red the moment the gate moved. The probe now arms both halves (it adopts a caps snapshot carrying the
resource consumer bit). **It is the first concrete instance of R-8's defect found in the tree.**

## 6. The 41 null checks — the walk, and the rule it needed

CONTRACT §7 names three cases and says "the rule generalises to all 41". Walking them turned up a third
rule the contract does not state, and without it the generalisation is harmful:

> **A probe moves only where "absent" is a CORRECT and SUFFICIENT answer.**

Where the fallback behind a probe produces a *right* result, "absent" is the accurate description of a
client that does not have the slot, and converting keeps the lane running. Where the fallback produces a
*silently wrong* result, converting would manufacture exactly the defect R-4 exists to prevent, and the
probe is left alone so the class-C slot Fatals **by name** — which is R-4's stated intent.

**Converted** (`MGL_BACKEND_SLOT_CAP` where a bit exists, `MGL_BACKEND_SLOT_LOCAL` where none does):

| site | slot | becomes | the fallback that survives |
|---|---|---|---|
| `GL_Query.cpp:481`, `:558`, `:785` | `BeginOcclusionQuery` | `kCapOcclusionQuery` | the target is rejected (GL's own answer) |
| `GL_Query.cpp:534` | `BeginXfbPrimitivesQuery` | `kCapXfbPrimitivesQuery` | CPU primitive accounting |
| `GL_Query.cpp` (begin) | `BeginTimeElapsedQuery` | `kCapTimerQuery` | a zero result |
| `GL_Query.cpp:660` | `QueryCounterTimestamp` | `kCapTimerQuery` | the same |
| `GL_Getter.cpp` ×2 | `GetGpuTimestampNs` | `kCapTimerQuery` | `0`, which `BackendObject.h:192` already names |
| `GL_Sync.cpp:59` | `FenceSync` | local | always-signaled syncs — **one gate carries the family**, because every later sync site is already guarded on `syncObject->backendHandle` |
| `GL_Texture.cpp:6537` | `GetTextureImage` | local | the frontend's own CPU readback, which is exact |
| `GL_Texture.cpp:6799` | `GetTexImage` | local | the same |
| `PipeFill.cpp` | `SubDataResident` (op table, not a slot) | `kCapResidentSubData` | the non-resident upload path |

**Not converted, deliberately:**

- the **transform-feedback span family** (`GL_Drawing.cpp:1274/:1290/:1371/:1420/:1435/:1641/:1673`). The
  frontend reads a null `EndTransformFeedback` as *"this backend does not own the capture, so reorder the
  captured records for it"* (`FixupGsStripCaptureOrder`). Under split the server's backend **does** own
  it, so "absent" would reorder a capture already in GL order — a silently corrupt buffer. XFB is off
  P5's reduced path and its slots are class C, so the first XFB call aborts by name. **This family is the
  first that will need a new `MGPCapBit`**, and that is an `MGPipeTypes.h` edit, i.e. c0's.
- `GL_Drawing.cpp:844` `PatchParameteri`: "absent" means the patch size is silently never set.
- the **28 unguarded slots**: no probe to convert, and `Fatal{UnmigratedVerb, "<slot>"}` is strictly
  better than today's undiagnosed null call.

In a pull build both macros expand to exactly the check they replaced, so codegen is unchanged (G1).

## 8. What v1 and the integrator most need

1. **`ClientSession::ScopedApplierEntry`** (new, `ClientSession.h`). v1's apply loop must bracket its
   `PipeWireDecoder::DecodeAndApply` with it. Without it `ApplyThreadIsInsideApplier()` is permanently
   false and R-1's mutual-exclusion assertion never fires — which is a gate that cannot go red for its
   own reason.
2. **The hook order in `MG_Backend::Init()` is load-bearing.** It must be:
   `ClientSessionInstance().Start(...)` → `pActiveBackendObject = MakeUnique<BackendObject_Remote>()` →
   `InitSpecificBackendLibs()` (which copies `GetBackendFunctions()` into `gBackendFunctionsTable`) →
   `LogBackendInfo()`. The client tolerates the snapshot arriving late — `PumpControlPlane` runs again
   from `Initialize()`, `InitCapabilities()` and every `Present` — but `ServerSession::SetBackend()`
   before `Accept()` is what makes the FIRST log line accurate.
3. **`WireVerbSink`'s five arms and what the records carry.** `OnClear` gets `Kind == kRemoteClearWhole`
   and `BufferMask`; the `Fbo` is deliberately null (§3). `OnDrawVbo` gets `IndexSize == 0`,
   `NumDraws == 1`, one `MGPDrawRange{first, count, 0}`, `Flags == 0` (never `kDrawHasUserIndices`).
   `OnReadPixels` must write **exactly `MGPReadbackInfo::DstSize`** bytes into the reply slot with
   status OK — the client computed that number from the pack state and already checked it against
   `MaxReplyBytes()`, so a short write is a silently truncated picture. `OnPresent` gets
   `FrameSerial == 0`, meaning "stamp your own".
4. **THE BIGGEST OPEN ITEM IN THE PHASE, and it is neither mine nor obviously anyone's: the 37
   `MGPipeApply*` entry points have NO client-to-wire routing anywhere in the tree.** The decode-side
   hook exists (`gMGPipeWireRecordApply`, `generated/PipeWire.inc:871`); there is no encode-side twin, and
   nothing in `MG_Impl/Pipe` or `MG_Pipe` branches on `MG_Config::Transport` to produce one. So under
   `inproc` today every resource / CSO / texture / sampler / program record still executes
   **synchronously on the GL thread**, against a context that v1 is moving to the apply thread — where
   all 16 `IsBackendContextCurrentOnThisThread()` and 16 `CanTouchGLNow()` guards answer *false*.
   `ClearThenReadPixels` may survive that; `TriangleScenario` needs a VBO and a program and will not.
   **This decides whether the first inproc frame renders**, and it needs an integrator ruling on owner
   and shape before v1 and c1 can be joined. `ClientSession::EmitAndWait` is already the whole client
   half of it — it takes an opcode and a payload — so the missing piece is one hook in `MG_Pipe` plus the
   37 call sites, not a new mechanism.
5. **Two unit cases were already red at the merge base, before c1 touched anything**, and c1 changes
   neither file nor any generated table they read:
   - `PipeWireCodecTest.NoReplyIsWrittenForARowTheCatalogueGivesNoReplySlot` — line 1203 asserts
     `MGPipeCallFlagsFor(ResourceCreate) & kReplySlot == 0`; **ID-31 gave that row the flag**, so it reads
     16. Pure ID-31 fallout: the test states the pre-ID-31 catalogue.
   - `RingTest.TheTwoFlagSpacesAreDisjointByTranslation` — line 774, the runtime half.
6. **One knob was invented and is flagged rather than smuggled:** `MOBILEGL_IPC_E2_DROP_CLEAR=1` arms
   E2's control (below). It is read with `getenv` in `EmitTables.cpp`, **not** through `MG_Config`,
   because `Config.h` is c0's; it warns loudly every time it arms. Adopt it into `IpcTable` or tell me to
   take it out.
7. **`MGPCaps::FormatCapabilities` / `RendererInfo` blobrefs are zeroed on adoption.** They name
   SEG_STAGE runs owned by the *server's* encoder; a later client-side reader that resolved one would
   read whatever the stage allocator has since put there.
