# What you build

1. **`BackendObject_Remote`** — 8 pure virtuals + 9 EGL lifecycle virtuals. Three traps from the scout: `GetRendererInfo()` returns a **reference**, so the object must own a `RendererInfo`; `GetFormatCapabilities()` is **non-virtual**, so you must *fill* `m_formatCapabilities` rather than override an accessor; `GetBackendType()` must answer the **server's** backend, never a new "Remote" enumerator, because frontend branches switch on it. And `LogBackendInfo()` reads `GetRendererInfo()` at `Init.cpp:21`, **before any surface exists** — return a placeholder and accept one imprecise startup log line; do **not** restructure `MG_Backend::Init()`.
2. **The emit table: 71 function pointers, not 69.** `Present` and `SetSwapInterval` have **zero `MG_Impl` call sites** — they are reached through the EGL path — so a table built by mirroring GLImpl covers neither, and `Present` is on the reduced path. **No slot may be null and no slot may fall through to the driver.** The three classes are already decided in CONTRACT §7: class A answered locally from the caps mirror (`GetIntegeri_v`, `IsTimerQuerySupported`), class B emitted (`Clear`, `DrawArrays`, `ReadPixels`, `BlitFramebuffer`, `Present`), class C `Fatal{UnmigratedVerb, "<slot>"}` (the other 64).
3. **The cross-cutting rule that is easy to miss and is written into CONTRACT §7:** **41 of the 69 slots are null-checked at their call site, and several of those null checks are capability probes, not safety checks.** Since no slot may be null, every one of those probes would answer "supported" and the fallback behind it would silently disappear. **A null check on a slot may never survive into the client under split** — it becomes a caps-mirror read. Three named cases are in the contract (`GL_Query.cpp:481`/`:785`, `GL_Query.cpp:534`, the `SubDataResident` op-table slot); the rule generalises to all 41, so walk them.
4. **`CapsMirror`** — the client's copy of the snapshot, answering the 56 caps read points. **Re-arrival of a snapshot *is* the invalidation** (R-12), so there is no separate `Invalidate()`; `Generation()` is the only thing on the client that can see a server context death, and a client memo must key on it.
5. **The verb barrier (R-1).** Publish, then wait `appliedSeq >= mySeq`, spin `MOBILEGL_IPC_SPIN_US` then park. **The barrier's wait and the reply's wait are the same wait** — that is why `ClientSession::EmitAndWait` is one call. Splitting them is how a package ends up re-deriving an acceptance answer locally, which R-5 forbids: the four `Bool` acceptance entry points and `MapPersistent`'s decline come back through the reply slot (c0 has now given those four rows `kReplySlot`, so `MGPipeCallFlagsFor` is the single source of truth). **Do not re-derive acceptance on the client, and do not "always accept"** — that is ID-39's 66 lost DirectVulkan uploads with a wire in between.
6. **R-8: the liveness gates read the caps mirror, never `MGPipeGetResourceOps()`.** `MGPipeResourceSubsystemEnabled()` and `P4aFamilyHasItsConsumer()` must ask `CapsMirror::ServerConsumes(subsystemBit)`. Under inproc the old read answers correctly *by accident*; under spawn the client has no backend at all and five families silently stop emitting while the client clears its dirty flags anyway. s1 already made the server end `Fatal` when nobody sets the mask; you are the client end.
7. **Blocking `read_pixels`** — copy the pixels out of `SEG_REPLY` into the application's pointer. The **PBO** destination half (fire-and-forget + client-side `MarkGpuWritten`) is b1's design; wire it, do not redesign it.
